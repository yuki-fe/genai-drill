RAGとファインチューニングの違い

RAG はモデルはそのままで、質問のたびに関係する文書を検索して、その内容をもとに答えさせる方法です。ファインチューニングは、追加の学習でモデルそのもの（重み）を変える方法です。

表で比べる

観点RAG（検索拡張生成）ファインチューニング
モデルの重み変えない追加の学習で変える
新しい情報を足すとき検索する文書を入れ替えれば、すぐ反映できるもう一度学習させる必要がある
得意なこと最新の情報や社内の文書をもとに答える、根拠の文書を示す決まった口調や出力の形、特定の分野の言い回しに合わせる
必要なもの検索する文書と、検索の仕組み（ベクトルデータベースなど）学習用のデータと、学習の計算

見分けるポイント

  • 「検索」「外部の文書」「学習し直さない」が出てきたら RAG
  • 「追加で学習」「重みを調整」が出てきたらファインチューニング
  • 情報がよく変わる用途や、根拠を示したい用途は RAG が向く
  • RAG は根拠の文書を使うのでハルシネーションを減らせるが、なくなるわけではない
  • 両方を組み合わせることもある

試験での出され方

「社内の規程が変わるたびに、すぐ答えに反映したい」のような場面で、どちらが向くかを選ぶ問題が考えられます。最新の情報を使いたい・根拠を示したい場面は RAG、と覚えましょう。

それぞれの用語

  • RAG（検索拡張生成）

    質問に関係する文書を検索して、その内容をもとに生成AIに答えさせる仕組み。モデルを学習し直さずに、最新の情報や社内の情報を使え、ハルシネーションを減らせる。

  • ファインチューニング

    学習済みのモデルを、目的に合ったデータで追加で学習させて、特定の用途に合わせること。
